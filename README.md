# MarginSentinel: Graph-Powered Return-Risk Scorer

A defense-only, graph-powered Machine Learning system built to prevent E-commerce Cash-on-Delivery (COD) Return-to-Origin (RTO) fraud and abuse rings.

## Why We Created This Project
E-commerce businesses in India face massive revenue bleed from **Return-to-Origin (RTO)** fraud—specifically in Cash-on-Delivery (COD) orders. Fraud rings and malicious actors exploit the COD model by repeatedly ordering items and rejecting them upon delivery, causing merchants to eat the cost of forward and backward logistics.

Traditional rule-based fraud engines fail because they treat every transaction in isolation. Attackers bypass these rules by rotating IP addresses, emails, and phone numbers. **MarginSentinel** was created to solve this by looking at the *hidden connections* between transactions. By representing users and their devices as a graph, the system can instantly identify "Sybil attacks" (one device controlling dozens of fake accounts) and camouflaged abuse rings, shutting them down before the package is ever shipped. 

Furthermore, this system was designed to be **strictly defense-only** (adding dynamic checkout friction like requiring a UPI pre-auth) and mathematically optimizes for the financial bottom-line, balancing the cost of a False Positive (losing a good customer) against a False Negative (shipping a fraudulent package).

## What This Project Does
1. **Dynamic Entity Resolution Graph:** As transactions occur, they are mapped into an in-memory graph connecting the transaction, the customer, and their device identifiers (`client_canvas_hash`, `app_set_id`, `vpa_handle_hash`).
2. **Sequential Feature Extraction:** When a new transaction arrives, the system calculates graph-based features in real-time, such as the size of the connected device component and the historical RTO rate of its graph neighborhood.
3. **Cost-Optimized Scoring:** A CatBoost classifier processes these features alongside traditional order features (cart value, checkout velocity, address quality). Instead of arbitrary thresholds, the model's decision boundary is mathematically chosen to minimize the total INR loss based on defined merchant costs.
4. **Actionable Defense:** The API returns a risk score and a specific defense action: `ALLOW_FREE_COD`, `REQUIRE_UPI_PREAUTH`, or `BLOCK_TRANSACTION`.

## Technology Stack

### 1. Data & Machine Learning (`src/`)
- **Python, Pandas, NumPy:** Core data manipulation and processing.
- **NetworkX:** Used to build the live entity-resolution graph and compute critical features like `connected_component_size`.
- **CatBoost:** The core gradient boosting classifier chosen for its native handling of categorical features and robustness against overfitting.
- **Scikit-Learn:** Used for robust data splitting (e.g., `GroupShuffleSplit` on ring IDs to prevent data leakage) and evaluation metrics (PR-AUC, Precision, Recall).
- **SHAP (SHapley Additive exPlanations):** Used to break down and interpret the model's decision for every single transaction, ensuring full explainability.

### 2. MLOps & Experiment Tracking (`src/`)
- **MLflow:** Used for experiment tracking, metric logging, and model registry. It is configured to run on a local file-store backend to record hyperparameter sweeps, financial cost curves, and save the finalized CatBoost model artifacts.

### 3. Backend Serving (`api/`)
- **FastAPI:** Provides a lightning-fast, asynchronous REST API (`/predict`) to serve the model in real-time.
- **Pydantic:** Ensures strict schema validation for all incoming transaction payloads.
- **Uvicorn:** The ASGI server used to run the FastAPI application.

### 4. Frontend Dashboard (`frontend/`)
- **Streamlit:** Powers the interactive Merchant Risk Dashboard.
- **Plotly:** Used for rendering dynamic gauge charts, SHAP feature importance bar charts, and financial optimization curves.
- **Pyvis:** Integrates with Streamlit to render the live NetworkX entity-resolution graph directly in the browser, allowing merchants to visually inspect the fraud ring structure.

### 5. Testing & CI/CD (`tests/`)
- **Pytest:** Contains strict regression suites, particularly focused on asserting zero data-leakage during the leave-one-out graph feature extraction process.

## Architecture & Directory Structure
- `data/`: Contains the synthetic dataset generation scripts.
- `src/`: ML pipeline (EDA, preprocessing, graph feature extraction, training, evaluation).
- `api/`: FastAPI backend serving the loaded MLflow model and keeping the graph state.
- `frontend/`: Streamlit dashboard for simulation, model diagnostics, and financial impact reporting.
- `reports/`: Markdown reports and PNG charts generated by the ML pipeline.
- `tests/`: Pytest suite.
